## 3. 最终目标结构（11 号图 v2 当前版本）

**7 个大级：** S0 `subcore_fetch`（每个 subcore 一份 `ifetch_frontend`，L1I、miss queue、TLB 留在 SM 层，F1）→ S1 `subcore_decode`（IB 读出加译码一拍，预译码给出源 / 目的、tap、目标前门和 valu_var 位）→ **head FIFO**（每 warp 2 项，在 S1/S2 边界上，读口送 S3）→ S2 `subcore_issue`（单拍环：eligible×16 → pick → issue = 选中 & credit_ok & rdy_s3）→ S3 `subcore_dispatch`（payload 译码、取 lane mask、按"通道 + opcode"分流；变长指令直接推入队列，推入一定成功；有 1 项保持寄存器）→ S4 `subcore_operand`（s0 allocate 加 reuse 标签，s1 读 rounds = 0…3 拍，执行起点 e = a + rounds，E17）→ S5 `subcore_exe`（固定延迟单元：VALU 6 级，tap 3/4/6，有 wb 和 wb2 两个出口；SALU 4 级；ELECT / VOTE / VOTEU / CREDUX；`sreg`）→ SW `subcore_wb`（RF B0/B1、P、URF、UP，RF init walker，写口仲裁）。

**前门（变长路径）：** 队列是 S3 和前门之间的桥，不归任何一级。

| 队列 / 前门 | credit | 模块 |
|---|---|---|
| LSU 8 / AGU 2 | 8 / 2 | `subcore_fd_mem`（exec_mem_issue、membar_track、AGU UR 读） |
| SFU/XLANE | 18 | `subcore_fd_sfx` |
| CBU | 1 | `subcore_fd_cbu` |
| 控制 | 1 | `subcore_ctrl_fd`（分支、收敛、EXIT、NANOSLEEP） |
| TQ 8 / async 2 | 8 / 2 | `subcore_frontdoor` |
| FP64 | 5 | `subcore_fd_fp64`（5 项操作数队列加 4 项结果队列） |
| valu_var | 1（加上 pair 中的一条，在途最多 2 条） | `subcore_fd_valu_var` |
| 常量（LDC / ULDC） | 1 | `fd_const`，暂定 R4，**还没有实现** |

**S4 的四张表：** ① 每 bank 一张读口表（`tbl_rd_b0_q/b1_q`），带防饿死保留位；② 按写口分的写回拍表（B0、B1、P×2、URF、UP），带写口防饿死保留位（B3）；③ VALU 出口计数，每拍不超过 2（ELECT 类和 rd = RZ 的结果也计入，E1、E6）；④ VALU / SALU 入口拍表。另有 reuse cache。allocate 停住时，全 subcore 的 stall 计数一起冻结（A11）。

**credit 机制：** S2 每个队列有一个 credit 池，池的大小等于队列深度。发射时减 1；前门读完操作数后寄存一拍，经 `ev_credit_return` 加回（A13）。所以对 S3 来说，变长路径的 rdy 恒为 1。

**事件通道（全部是源级寄存，目的级下一拍看到）：** `ev_head_consumed`（S2→S1），`ev_complete`（SW→S2），`ev_credit_return`（前门→S2），`ev_branch_resolve`（控制前门→S2，分 COMMIT / SPLIT / DROP 三种，经 S2 侧 2 项 FIFO，前门持 2 个 credit），`ev_phasechk`（CBU 前门→S2），`ev_redirect`（S2→S0），`ev_exit` / `ev_fetch_need`（S2→S0，R5c），`ev_wb_wait`（SW→S4，E5），`ev_membar_done`、`ev_l1_inv_done`、`ev_setmax_done`、`ev_rf_init_done`，以及待定的 `ev_tmem_done`（G5）。另有 §3-3a 规定的唯一一种反向**完成信号**：S3 / S4 的在途掩码点对点送进 S2（R3）。上下文链由各级各扫自己的状态，顶层只负责串链（C1）。

## 4. 关键设计决定（选 10 条）

1. **B1 / E21 / E24：固定路径不反压，变长路径靠 credit。** S5 和 SW 的 rdy 恒为 1，原来的 `fu_busy`、`fp64_busy`、队列满反压都删掉。效果已经看得到：E24 落地后，port_pressure 周期 −7.2%，因为固定延迟的 VALU 不再被变长序列挡住（`fecf774c8`）。
2. **E24：valu_var 不建统一的操作数队列，credit 只表示在途条数，取值 1。** 如果按图建队列，要在现有 staging 之外再加约 12K 个触发器；实际每个序列的 staging 只能放 1 条，所以 credit 定为 1，加上 pair 里的一条，在途最多 2 条，与性能模型的深度 2 一致。
3. **E21：每个前门是独立模块，队列做成顶层的桥，跨前门的仲裁归 SW。** 前门之间不再互看状态，改成"请求 → grant"。
4. **E1 / E6：ELECT、VOTEU、rd = RZ 的结果不占 GPR bank，只计入 VALU 出口。** 去掉白占 bank 造成的假冲突，图按 RTL 现状改。
5. **R2 / E7 / E8：guard 在前门队头读。** 给前门加第二个谓词读口，每个前门一个专用行读口，S3 不再需要谓词读口。前门读 guard 比原来晚，由读 scoreboard 保护（E18 让编译器给名单外、带谓词的 CBU 指令也设读 scoreboard）。
6. **R3 与规范 §3-3a：完成信号。** 采用用户的方案（参考 DSP.v 的 `exit_ena` 写法），不采用 S2 自己计数：在途掩码从下游寄存器译码，点对点送进 S2，在 S2 里先寄存再用。
7. **E9 / E13 / E14：分支序列。** 控制前门只发寄存的 `ev_branch_resolve`，ITS 只由 S2 写；advance 由 S2 自己做；split 不再握手，改成 2 项 FIFO 加 credit；前门根据本地记录推断事件何时落地。
8. **E20 / E22：** head FIFO 做成 2 项，S3 加 1 项保持寄存器，去掉 S3 → S1 的反向 hold。不过同一 warp 背靠背发射时 ITS advance 会落后一拍，所以第一版保留 `advance_pending`，每个 warp 仍是 2 拍一条，这是与性能模型的已知差距。
9. **D5：collect 状态机就是串行的读窗口。** 按"先保持行为、再放开重叠"分步做；VALU / SALU 的操作数视图归 S4，ELECT / CREDUX 的读序列也归 S4 读窗口（图 `4e2b425`）。
10. **R1 / R4 / R5：** ELECT 的延迟按 RTL 定为 1 拍（性能模型和编译器的表从 2 改为 1）；LDC、R2P、S2R 等指令暂定分配到常量前门或 valu_var，以后逐条复核；S0 搬进 subcore 的接口已经定好，包括用 `l1i_miss_credit` 取代组合的 `fr_ready`，但实际搬迁推后。

**流程上的规则（用户定）：** 单个提交周期变长超过 5% 不再停下，只记录原因后继续，功能失败仍然停；实现中发现设计问题时，先改结构数据并重新生成图，再继续实现（设计请求 R1–R6）。

## 5. 工作中发现的真实问题

| # | 问题 | 怎么发现 / 如何修复 |
|---|---|---|
| 1 | **在途 warp 掩码写成 `16'hffff << slot`**，会把编号 ≥ slot 的 warp 全部标成在途，应为 `1 << slot`。功能上安全，但多 warp 时 MEMBAR / ERRBAR 会偏慢。G3b-2A 引入 | 设计对话审查时发现，`acdab4ae8` 修复；现有用例都没覆盖到，周期不变 |
| 2 | **IEEE 1800 可移植性**：`issue_dispatch_splinter_id_int` 的驱动在搬迁时被误删。Verilator 把未驱动的线当 0，VCS 里是 Z 并传成 X，smk_add 卡死。另外断言属性里调用的函数在两个仿真器上采样时机不同 | VCS 编译时暴露，`7535ae401` |
| 3 | **shared / local 读后写漏洞**：LDS 被 smem_ctrl nack 后，年轻的同地址 STS 可以先写，编译器没有为这种情况设等待 | E10 分析。新用例 smem_war 用旧编译器复现：nack 7691 次中 **96 次读到新值**；新编译器 0 错（`bcbdf744b`、`d7a55f040`） |
| 4 | **shared allocator 区间重叠**：大小不同的 CTA（9216 / 1536 字节）并发时地址会重叠 | `ce7b32910` 改为 first-fit |
| 5 | **多 warp 时 ELECT 选错 lane**：bulk copy 被发两次，mbarrier 永远等不到 | 只在每个 subcore 多 warp 时出现；`f4ab607e8` 修复，并新增 mix 用例 |
| 6 | **ELECT 写 P 会被第二个 P 口丢掉**（B5 之后），本来能发现它的断言从未进入运行列表 | `1e9329a6d`；之后断言改为全部 50 个文件都跑 |
| 7 | **验收脚本漏判**：SoC 跑完有 SM fault（wb_overcommit），但脚本只看 PASS 行 | `accept.sh` 改为同时要求没有 fault，并有 workload 自己的 PASS 行 |
| 8 | SALU 直通路径上 `bool_op` / `ex` / `sat` 没有驱动，读作 0 | `cc886da63`；按 E23 统计，直通路径只出现在 S2UR / UMOV |
| 9 | 同一 warp 背靠背发射时 ITS advance 晚一拍，pred_branch 等用例出错 | E22，暂时保留 `advance_pending` |
| 10 | sm_context 的 Verilator 构建从 10-16 起一直失败；8 个断言文件编译不过 | `f47101c21`、`0f6ac2d3d` |

**perf-gap（`runs/perf-gap/README.md`）：** RTL 与模型的 kernel 周期比为 7–14×（iadd3 89,225 对 6,330；mix 115,526 对 16,023；control_flow 106,338 对 15,072），但主体是**计时窗口内没有任何发射的 85–92k 拍**，两边计时口径不同：RTL 的 `SOC PERF` 包含约 73k 拍 FECS 首次装 GR 上下文，模型只计 581 拍。subcore 能影响的发射跨度比只有 1.3–2.7×。用同一口径（第一个 CTA 启动到最后一个 CTA 退出）比，iadd3 只差 **1.2–1.3 倍**。发射跨度的差距主要来自访存：RTL 上 STG 每约 128 拍才发一条（模型 4 拍），常量缓存未命中约 1100 拍对 590 拍。STG 的问题追到编译器的有序等待（R6 → E10，去掉了 global store 之间的等待），以及模型的写路径没有反压（第 11 项）。

**align13：** 性能模型的发射事件按（CTA, warp）分组后，可以与 ISS 的序号逐条对齐，3 个用例共 288 / 6494 / 8782 条，0 个不一致。顺带发现模型里同一 warp 间隔 1 拍发射很常见，而 RTL 至少 2 拍，这就是 E22 的那个差距。

**C1 第一处分歧检查（`runs/C1/summary.md`）：** 当前 RTL 跑 6 次，0 个分歧线程；对 G2 的错误版本，3 个用例都在 kernel 第 2–3 条指令就报出分歧，并直接指向"ITS PC 推进晚一拍"。
